# Today program selector — iOS

Пул: COA-8228, COA-8230, COA-8227, COA-8232, COA-8231. Реализация находится в
`TodayProgramSelectorTests`; существующий COA-8235 сохранён. COA-8229 проверяется
в составе открытия/закрытия селектора, без отдельного полного E2E.

[Готовое покрытие и результаты](ready-ios-autotests.md) включают оба этапа селектора и проверку восстановления после сбоя.

## Запуск

Используется существующий Keychain runner. COA-8228/8230/8227 используют
подтверждённого returning-user COA-8235 без изменения программы/прогресса.
COA-8232 и COA-8231 используют отдельные аккаунты. Тесты выполняются последовательно,
каждый заново авторизует фикстуру. Подписка и flags не изменяются.

```bash
python3 scripts/run_test_model_local.py COA-8230 COA-8228 COA-8227 --app "/path/to/The Coach.app" --maven=-q
# Однократный setup: существующие подтверждённые аккаунты сохраняются.
python3 scripts/run_test_model_local.py COA-8232 COA-8231 --provision --app "/path/to/The Coach.app" --maven=-q
python3 scripts/run_test_model_local.py COA-8232 COA-8231 --app "/path/to/The Coach.app" --maven=-q
```

Нужны запущенный Appium, iOS Simulator, `xcrun`, `ffmpeg` в PATH и Python 3.
Передайте Simulator-сборку через `--app "/path/to/The Coach.app"` во всех командах ниже.

## Проверки

| ТК | Проверки |
| --- | --- |
| COA-8228 | Жест вниз из заголовка sheet, исчезновение карточек, возврат Today; промежуточное движение верхнего индикатора модалки в видеокадрах вниз. |
| COA-8230 | Одна и та же видимая карточка сместилась вверх после вертикального жеста, горизонтальная позиция сохранена, селектор остался открыт. |
| COA-8227 | Выезд снизу в промежуточных кадрах; новое ProgramModalOpen после постановки observer; UID проверенной login-сессии; первая программа соответствует заголовку Today до открытия; непрерывная оранжевая рамка на четырёх сторонах карточки; скролл и совпадение списка с Explore через существующий reader/oracle COA-8235. |
| COA-8229 | Существующий outside tap, исчезновение и промежуточная анимация вниз в сценарии COA-8227. |
| COA-8232 | Выбор Keep It Hard закрывает модалку; выбрана вкладка Today; заголовок, модуль, этап и три карточки соответствуют свежему ответу текущего аккаунта; новое ProgramModalSelect с точным program_id=keep_it_hard; content → skeleton → content в видеокадрах. |
| COA-8231 | Last Longer первый и выделен; после выбора Keep It Hard и повторного открытия именно Keep It Hard первый и выделен оранжевой рамкой на четырёх сторонах. Регрессия COA-8253. |

Видеопроверка требует несколько разных промежуточных позиций и итоговое движение
в нужную сторону. Статичный кадр, мгновенный скачок и дрожание пикселей не дают
PASS. Численных требований к длительности или плавности анимации не добавлено.
Отслеживается короткий серый индикатор на белой поверхности sheet: при открытии
карточки могут появиться только после завершения выезда. Их цвет проверяется
отдельно по уже отрисованному экрану.
Цвет допускает антиалиасинг/сжатие; `selected=true` не заменяет проверку рамки.
Отсутствие наблюдаемого индикатора/кадров приводит к ошибке, не к пропуску теста.

Observer запускается до тапа и принимает только событие с новым ID SDK (UUID),
которого не было в исходном снимке очереди, timestamp не ранее начала наблюдения
и UID авторизованной фикстуры. Для старого формата без UUID используется хеш
payload. Номер строки SQLite сохраняется для диагностики, но его сброс не
мешает распознать новое событие. Observer сохраняет
минимальный JSON без email, OTP, user properties и полного payload.
Очередь опрашивается каждые 10 мс, поскольку SDK удаляет отправленные события.
Диагностика включает исходный размер очереди, число опросов, максимальный новый
ID и факт опустошения очереди. Это локальное наблюдение очереди SDK, а не
подтверждение доставки в Amplitude; события с временем жизни меньше интервала
опроса теоретически могут быть пропущены. При отсутствии события тест падает.

Видео, кадры и лог рекордера: `target/COA-*-motion-*`. Аналитика:
`target/test-model-evidence/COA-8227-*` и `COA-8232-*`. Видео и координаты, рамка и аналитика
прикладываются к Allure; при ошибке CoreTestCase сохраняет screenshot/page source
до cleanup. Открытый селектор закрывается при cleanup и после успешных проверок.

## Смена программы и восстановление

Для каждого изменяющего сценария runner создаёт отдельный email alias через
существующий onboarding и подтверждает повторный вход. Перед переключением тест
сверяет UID в текущей сессии с provisioned UID. Пара данных закреплена:
`last_longer` (Last Longer) → `keep_it_hard` (Keep It Hard), исходный прогресс 0%.
Программа, отображаемый день/этап и прогресс восстанавливаются через UI в `finally`.
Ошибка восстановления делает тест неуспешным; при исходной ошибке она сохраняется
как suppressed. Диагностика снимается до восстановления через общий sanitizer
CoreTestCase. После прерванного предыдущего запуска допускается возврат из
Keep It Hard в Last Longer только на UID-проверенном выделенном аккаунте.

Для проверки rollback при реальном сбое есть отдельный инфраструктурный сценарий:

```bash
python3 scripts/run_test_model_local.py COA-8232 --app "/path/to/The Coach.app" --maven=-q \
  '--maven=-Dtest=tests.TodayProgramSelectorTests#testProgramChangeFixtureRestoresAfterFailure'
```

Он намеренно бросает AssertionError после успешного переключения, проверяет
сохранение именно этой ошибки и подтверждает исходное состояние в UI.

`ProgramModalSelect` требует точного `event_properties.program_id`: отсутствующее,
другое или приведённое по типу значение не проходит. UID/время/UUID проверяются
так же, как у ProgramModalOpen. SDK-очередь не подтверждает доставку в Amplitude.

Контент сверяется с ответом `/api/v1/daily_program/v2/`, который само приложение
получило после текущего тапа. `read_simulator_program_content.py` читает только
локальный CFURL cache: проверяет UID и expiry JWT, timestamp после действия,
HTTP Date, program_id и section_id. Предыдущий ответ/другой аккаунт/неизвестный
формат cache приводят к ошибке. Запросов API и записи в cache нет. В Allure попадают
только разрешённые поля контента без Authorization/email/OTP. Текущий формат
request Version 9 / response Version 1 проверен на iOS Simulator 26.5.

В сборке 1.13.29 лоадер — две серые skeleton-заглушки заголовка и модуля Today.
Они могут появиться и исчезнуть позади ещё закрывающейся модалки. Oracle требует
наблюдаемое появление и исчезновение обеих областей с контентом до и после;
статичный экран, одно затемнение и незавершённая загрузка не проходят.
Геометрия основана на проверенном viewport 390×848 в видеокадрах, координаты
масштабируются. При изменении дизайна требуется перепроверить визуальный oracle.
Численного порога длительности загрузки в ТК нет. Отсутствие записанного лоадера
вызывает FAIL, без пропуска или UI-retry. Ответ и loading evidence сохраняются в
`target/COA-8232-content-*` и `target/COA-8232-motion-*` и прикладываются к Allure.

COA-8253 проверяется поведением после переключения. Успешный прогон относится к
конкретной сборке и фикстуре; статус дефекта в Jira автоматически не меняется.

Jira/Xray не изменяются этим runner.
