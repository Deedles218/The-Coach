У каждого подтверждена почта, выполнен выход и успешный повторный вход.
Создание аккаунта **не означает**, что все предусловия его теста готовы.

## Хранение данных

Локальный реестр находится в macOS Keychain: service
`the-coach-test-model-accounts`, account — текущий macOS-пользователь.
Адреса — алиасы согласованной временной почты с суффиксами `+coa8511`,
`+coa8512`, `+coa8517`, `+coa8518`. Секретные значения не записаны в исходники.
Реестр содержит email/OTP, подтверждённый UID, статус регистрации и отдельный
статус fixture. Runner передаёт данные в `TestData` через окружение процесса.

```bash
python3 scripts/run_test_model_local.py --status
python3 scripts/run_test_model_local.py COA-8511 COA-8512 COA-8517 COA-8518 --provision
python3 scripts/run_test_model_local.py COA-8235 COA-8517 --maven=-q
```

`--provision` сохраняет уже подтверждённые аккаунты. Защищённый аккаунт
пользователя не использовался для мутаций. Аккаунты не удалялись; покупки,
списания и изменения глобальной Firebase-конфигурации не выполнялись.

## Реализованный reset COA-8517

Используется базовый вариант Overall Health с практиками, не `theory_only`.
Fixture-карточка — `exercise_meal_plan_check` / **Check Your Meal Plan**.
Контент задаёт её на дни 2–70; в день 1 она не предусмотрена.

Перед тестом UID проверяется по подтверждённому email через preprod
`get_user_info`. Заголовок текущей авторизованной Simulator-сессии используется
только в памяти и только при совпадении UID с выделенным аккаунтом.
Если предыдущий прогон прервался после удаления, setup восстанавливает только
эту карточку через API, проверяет её контент/расписание и снова удаляет её.
Удаление карточки обратимо и не является удалением аккаунта.
В фактическом запросе приложения `action_titles` содержит технические ID:
`["exercise_meal_plan_check"]`, а не отображаемое `Check Your Meal Plan`.
После reset дополнительно проверяется исчезновение карточки из Removed exercises;
одного HTTP 200 недостаточно. Восстановление и повторный seed после прерванного
прогона отдельно подтверждены на живом preprod после исправления этого payload.

Само проверяемое восстановление выполняется через интерфейс. На сборке 1.13.29
кнопка называется **Restore**, а не RECOVER из старого ТК. Проверяется точная
карточка и переход `SettingsCheckBoxInactive → SettingsCheckBoxActive`, а не
любой checkbox. После закрытия окна API-проверка сравнивает ID/название карточки
и номер каждого из 69 дней — это не подсчёт одинаковых элементов на одном экране.
Перед этой сверкой отдельно проверяется отображение восстановленной карточки
в интерфейсе дня 2 в Explore.

Запрос `daily_program/v2` с `day_of_program` также меняет текущий день пользователя,
хотя использует GET. Поэтому сверка дней выполняется последовательно; в `finally`
штатный per-user инструмент возвращает fixture на день 2, и API подтверждает
полученный день. При ошибке возврата тест не может считаться успешным.
Это поведение описано в [документе «Новый Дейли План»](https://the-coach.atlassian.net/wiki/spaces/~5d4df609c54e920cf3b825a0/pages/3473408160).

Основание: [требование COA-8263](https://the-coach.atlassian.net/browse/COA-8263),
[API-контракт COA-8315](https://the-coach.atlassian.net/browse/COA-8315),
[описание Daily Program API](https://the-coach.atlassian.net/wiki/spaces/TES/pages/3480158229/Daily+Program+API+Documentation).
Смена варианта и перевод по дням выполнялись штатными **per-user** инструментами
preprod, описанными в [COA-8704](https://the-coach.atlassian.net/browse/COA-8704)
и [COA-9042](https://the-coach.atlassian.net/browse/COA-9042). В актуальном setup
вариант base и день 2 задаются автоматически перед каждым запуском.

## Состояние COA-8511

Выделенный аккаунт переведён на базовый Kegel Challenge. Карточка
`exercise_kegel_sport_w1_t1` / **Resistance Kegel Training** на дне 1 имеет
`allow_modification=true`; штатный `move_action_forward` перенёс её на день 2,
где API возвращает её в секции 3 (To Catch-Up), невыполненной и ещё не перенесённой
повторно. Для подготовки предыдущего дня через документированный
`action_completed` отмечен выполненным Morning Kegel Workout дня 1.

Подтверждены реальные UI-маркеры: `TitleBlock.Title` с label `TO CATCH-UP`,
контейнер `DailyPlanItem` и иконка первого переноса `ItemMovedForward`.
В Explore день 2 и нужная карточка отображаются, но long-press по контейнеру
и по заголовку не открывает меню. На Today попытка следующего этапа показывает
paywall; после закрытия Today остаётся на Stage 1. Проверкой в Explore нельзя
подменить отсутствующий end-to-end результат COA-8511 на Today.

Повторная проверка после отдельного входа в каждый аккаунт подтвердила:

аккаунтов: `target/test-model-evidence/blocked-audit-1788703165102.json`.
