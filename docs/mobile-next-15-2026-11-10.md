## Фикстуры и диагностика

Для подготовленных профилей требуется `TEST_ISOLATION_MODE=logout`,
`noReset=true`, `fullReset=false`, правильный For Him build, явный UDID и
отдельные последовательные запуски. `PreparedMobileProfile` проверяет
существующий аккаунт без OTP; на Android сравнивается полный email, на iOS
используются nickname и отсутствие CONNECT/CONFIRM. UID и происхождение
назначения программы этот helper не доказывает. Настройки reset в capabilities
нужно сверять отдельно: `assertPreservationAllowed()` проверяет только isolation mode.

- **Корзина:** английский UI, изначально пустая корзина, выделенный QA-аккаунт,
  `coach.cart.dedicatedAccount=true`, `coach.cart.product` с доступным товаром.
  Сценарий восстанавливает пустую корзину через UI даже при ошибке.
  COA-9365 требует Welcome на втором Android, другой UDID, отдельный
  UiAutomator2 systemPort, `coach.cart.second.appiumUrl` и рабочий OTP.
  Авторизация, проверка identity и badge входят в область обязательного logout;
  quit выполняется и после неудачной проверки Welcome. Ошибки logout/quit и
  возврата из Profile сохраняются как suppressed у исходной ошибки.
  Banner проверяется после selected-tab и `rvQuestions`/`catalogContainer`,
  исчезновения loading; отсутствие наблюдается 4 секунды. Это ограниченное
  окно, а не доказательство отсутствия баннера при любой задержке сервера.
- **Sharing:** For Him, Sex Is a Skill, доступный этап с Mastering Her Orgasm
  и Her Pleasure Anatomy, опционально `coach.sharing.preparedProfile=true`.
  Для COA-9490 задать `coach.sharing.unconfiguredLesson` и доступный этап.
  Код исключает два известных eligible-названия, но не читает конфигурацию:
  независимое подтверждение выбранного отрицательного урока обязательно.
  Android positive/negative используют один путь выхода player → lesson → Today
  (с подтверждениями, когда они показаны). SharingVideo не закрывается до oracle.
  Отсутствие наблюдается 4 секунды; ошибки драйвера не считаются отсутствием.
  Системный share preview читается без отправки сообщения.
- **Маркетинг:** отдельное устройство, `coach.marketing.dedicatedDevice=true`,
  `coach.marketing.dedicatedAccount=true`, `coach.marketing.case=COA-xxxx`,
  reviewed-ссылка через `COACH_MARKETING_LINK`, email/OTP через secret environment.
  Каждый метод требует собственный case/fixture, поэтому запуск всего класса с
  одним значением case не подходит. Ссылочные сценарии начинают с Welcome.
  Неожиданный GOALS до или после OTP вызывает явную диагностическую ошибку;
  обычные login helpers с автоматическим выбором goals не вызываются.
  COA-9404 не начинает другой Start flow, если ссылка не открыла GOALS.
  У неожиданного аккаунта cleanup не выполняет logout/reset. Для ссылочных
  методов logout разрешён только после успешной проверки ожидаемого профиля;
  COA-9388 и anonymous COA-9404 сохраняют свою подготовленную сессию.
  После холодного запуска COA-9388 ожидает Today без повторной авторизации:
  Login или GOALS считаются ошибкой, общий helper с выбором целей не вызывается.
- **Spanish PDF:** аккаунт без PDF, Spanish UI,
  `coach.pdf.spanishWorkbookLabel`, `coach.pdf.coverResource` из наблюдённого UI.
  Цена проверяется по наличию цифры/валюты и отсутствию placeholder-маркеров.
  Разнообразие цветов подтверждает непустую обложку, но не её соответствие
  эталону. Покупка и содержимое PDF не проверяются.

У Marketing нет независимого baseline до назначения: перед ссылкой открыт
Welcome. Совпадение итогового title и identity не доказывает, что именно этот
переход впервые назначил программу. Для COA-9388 происхождение назначения по
маркетинговой ссылке также **не проверено**. До live-прогона владелец фикстуры
должен подтвердить ссылку, case-to-account mapping, исходное состояние,
допустимую мутацию и ожидаемый маршрут. Этот пробел нельзя считать PASS или skip;
неизвестный маршрут остаётся ошибкой с явной диагностикой.

## Защита ссылок и диагностических данных

`TestData.sanitizeSensitiveData()` маскирует `COACH_MARKETING_LINK` до
обработки UID, включая исходный URL и его XML-представление с `&amp;`.
Проверка в отдельной JVM подтверждает чтение environment, оба представления
ссылки с UID в query и сохранение посторонней публичной ссылки. Обработка
existing-progress email/OTP сохранена. CoreTestCase использует sanitizer для
page source, driver logs, failure context и Allure; изменённый page source
также включает существующую защиту скриншотов с приватными данными.
Локальный Page Object не включает ссылку в `@Step` или сообщения ошибок и
не сохраняет исходное исключение Appium/URI parser. Для реального Appium
маскирование private URL и credentials в серверных логах остаётся задачей runner.

## Offline-проверка публикации

Текущая проверка выполняется без сети, API, браузера, deep links, Store,
устройств или Appium-сессий. Maven компилирует test sources, затем запускает
только явно перечисленные offline unit-классы; default UI suite не запускается.

```sh
git diff --check
mvn -o -B -DskipTests test-compile
mvn -o -B -Dtest=RestoringTestActionUnitTests,AndroidSharingExitUnitTests,AndroidCartCleanupUnitTests,AndroidCartBannerUnitTests,MarketingProgramContractUnitTests test
```

В финальной объединённой проверке публикации прошли 190 Java unit-тестов
в 22 классах и 27 Python-тестов аналитики, без failures/errors/skips.
Maven с `-Djava.awt.headless=true` скомпилировал все 336 Java test sources.
Компиляция и unit-проверки не считаются прохождением 15 UI-кейсов;
устройства, аккаунты, сеть и Appium в этой проверке не использовались.
