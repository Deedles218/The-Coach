## Аккаунты и ссылка

Передавать секреты через окружение, не через командную строку:

- `COACH_COA8096_EMAIL`, `COACH_COA8096_OTP` и отдельно
  `COACH_COA8094_EMAIL`, `COACH_COA8094_OTP`: готовый аккаунт с доступной
  **обычной** тренировкой Kegel в Today. Карточка Custom Kegel не заменяет её.
- `COACH_COA8170_EMAIL`, `COACH_COA8170_OTP` и
  `COACH_COA8171_EMAIL`, `COACH_COA8171_OTP`: выделенные аккаунты,
  на которых разрешено изменение состава Custom Kegel. Каждый тест выполняет
  новый вход заданными email/OTP через существующий Page Object. У разных одновременно работающих устройств должны
  быть разные аккаунты. Один аккаунт допустим только для последовательных запусков.
- `COACH_COA7937_LINK`, `COACH_COA7937_EMAIL`: предоставленные владельцем
  SIAS(M) ссылка и соответствующий email. OTP для этого кейса не используется.
  Данные из сообщения владельца не записываются в исходники.

LL(M), SIAS SQUIRT(M) и SIAS WOMEN в этот набор не входят.
Исключение из подготовки новым входом: Android fixture с `auth.flow=android-session`
для четырёх Kegel-кейсов использует выделенную сессию, заранее созданную вводом
email/OTP через UI. Передать `COACH_KEGEL_SESSION_EMAIL`, совпадающий с email
запускаемого кейса. Это декларация оператора о выполненном входе, не проверка
email в профиле. Тест ждёт авторизованный Today, сохраняет и восстанавливает
программу/прогресс/состав, затем оставляет авторизацию для следующего одиночного
запуска. Profile и logout через Profile не открываются, в том числе при ошибке
проверки. На каждом другом устройстве сессию необходимо подготовить отдельно.
COA-7937 этот обход не использует: его проверка по-прежнему требует профиль.

Подготовка и восстановление выполняются только через UI, без backend/API,
сброса прогресса или покупки. Используется существующий `RestoringTestAction`:
исходная ошибка сохраняется, ошибка восстановления добавляется к ней.

## Локаторы целевой сборки

Для четырёх Kegel-кейсов нужен UTF-8 `.properties` файл, указанный через `-Dcoach.kegelUi.fixture=...`.
Файл описывает **наблюдавшиеся** элементы конкретной сборки, не конфиг приложения.
Файл `src/test/resources/kegel/ios-preprod-1.13.29.properties` содержит наблюдённые
локаторы обычного Kegel, Guide, info и нативного Custom Kegel в Retain.
Для Custom выбран `custom.flow=ios-catalog`: удаление через редактор,
добавление через каталог с SAVE, интенсивность через native picker wheel.
Отсутствие данных приводит к явной ошибке, без skip и без подмены сценария.

Для присланного Android APK добавлен
`src/test/resources/kegel/android-prod-1.42.1.properties`. Путь обычной тренировки:
Today → Kegel Challenge → Morning Kegel Workout; путь Custom:
Today → Last Longer → Last Longer: Retain → Custom Kegel Training.
Android-подсказки переключателя находятся в отдельном окне; fixture включает
`enableMultiWindows`. Непрерывная анимация упражнения не становится idle,
поэтому только в этой подготовке `waitForIdleTimeout=1000`; действия продолжают
использовать явные ожидания. Перед паузой ожидается именно Inverted Clasp,
а не READY. Поле `player.expectedExercise` задаёт это ожидание.

В `custom.flow=android-catalog` общая длительность включает отдых, поэтому
не приравнивается сумме длительностей строк. До мутаций проверяются развёрнутый
непрокручиваемый RecyclerView, полный список между границами viewport/Start/Add,
непрерывность строк и их верхняя/нижняя границы. После сокращения списка мелкая
прокрутка выводит обрезанную верхнюю строку целиком. Нулевой скрытый список
допустим только без строк и при общей длительности 0. Для системного выбора
интенсивности используется наблюдённый NumberPicker; после выбора проверяются
устойчивое значение и его перенос в редактор. Активная SAVE имеет отдельный ID
`btnSaveActive`, SELECT — `btnSave`. Перед SAVE каталога проверяется устойчивый
выбор ровно одного нужного упражнения; XML этого состояния прикладывается в Allure.
Активность Start на Android проверяется по сочетанию `enabled && clickable`;
до проверки в Allure сохраняются оба атрибута и XML экрана. На этой сборке
при пустом списке оба атрибута остались `true`, поэтому кейс не прошёл.

| Ключи | Требование |
| --- | --- |
| `platform`, `app.version`, `environment` | `ios` / `android`, версия, среда. Версия/среда — метаданные оператора; они не определяются автоматически и должны совпадать с установленной сборкой. |
| `regular.program`, `custom.program` | Название программы в переключателе. Для обычного Kegel наблюдался Kegel Challenge; для Custom — Last Longer: Retain. |
| `regular.card`, `regular.screen` | Карточка обычного Kegel в Today и маркер экрана перед стартом. |
| `regular.stretching`, `regular.start`, `player.pause`, `player.paused` | Переключатель Stretching PF, Start и состояния кнопки плеера. Переключатель временно выключается через UI и восстанавливается до выхода из аккаунта. |
| `workout.identity`, `player.phase` | Текущее выбранное упражнение в плеере и остановленная инструкция; не таймер и не общий заголовок «Kegel». На наблюдённой iOS-сборке отдельного названия всей тренировки в плеере нет. |
| `guide.open`, `guide.screen`, `guide.close` | Штатная кнопка Guide, уникальный маркер гайда, крестик. |
| `info.open`, `info.screen`, `info.title`, `info.content`, `info.close` | Кнопка `i`, уникальный маркер окна, заголовок, описание, крестик. |
| `info.expectedTitle.<упражнение>`, `info.expectedContent.<упражнение>` | Ожидаемые заголовок/фрагмент описания для значения `workout.identity`. В iOS-файле закреплён Inverted Clasp; другой контент требует предварительного закрепления ожиданий. |
| `custom.card`, `custom.screen`, `custom.start`, `custom.add` | Карточка в Today, экран редактора, Start, Add exercise. |
| `custom.rows`, `custom.count` | В общем контракте: полный упорядоченный список строк и отдельный UI-счётчик. В `ios-catalog` счётчика нет; используется независимая общая длительность, см. ниже. |
| `custom.row.title`, `custom.row.remove` | Локаторы относительно строки: название и удаление. Для XPath использовать `.//`, а не глобальный `//`. |
| `custom.confirm`, `custom.cancel`, `custom.delete` | Маркер подтверждения, Cancel и подтверждение удаления. |
| `custom.picker`, `custom.picker.close`, `custom.pick` | Каталог упражнений, закрытие, XPath выбора по точному названию. В `custom.pick` обязательный `{value}` заменяется корректным XPath-литералом; дополнительные кавычки вокруг него не ставить. |
| `custom.editor`, `custom.editor.close`, `custom.save` | Редактор добавляемого упражнения, отмена, сохранение. Save должен возвращать к списку тренировки. |
| `custom.fields` | Через запятую все изменяемые параметры строки, например duration,intensity. Реальные поля определяются по сборке. |
| `custom.row.<поле>` | Значение параметра относительно строки. |
| `custom.edit.<поле>`, `custom.option.<поле>` | Открытие выбора параметра и XPath точного значения с `{value}`. |
| `custom.optionSave.<поле>`, `custom.optionCancel.<поле>` | Необязательные кнопки подтверждения/закрытия отдельного выбора. Для модального выбора нужна кнопка отмены, чтобы восстановление могло закрыть его после падения. |

Форматы локаторов: существующие проектные `id:` и `xpath:`; предпочтительны
accessibility/resource IDs. Для Android использовать package установленной сборки.
Выбор программ переиспользует существующие платформенные Page Objects.
У iOS-метода `selectExactProgram` изменена видимость с private на public и добавлено
экранирование названий с кавычками; поведение существующих сценариев сохранено.

До выбора программы сохраняются её название, день и процент прогресса.
После сценария проверяется неизменность прогресса Kegel, затем через переключатель
восстанавливается исходная программа и сверяются все три исходных значения.
Восстановление выполняется до logout, в том числе при ошибке подготовки/проверки.
Крестик Guide/info закрывается и при незагрузившемся содержимом окна.

Ограничения Custom Kegel fixture: маленький список, целиком представленный в
дереве UI; исходные упражнения доступны в каталоге, допускают добавление в
исходном порядке со всеми сохранёнными параметрами. Перед удалением размер
списка сверяется с UI-счётчиком общего контракта. В наблюдённом `ios-catalog`
UI-счётчика нет: сумма положительных длительностей всех строк сверяется с
общей длительностью из заголовка. Это обнаруживает пропущенные строки,
включая дубликаты; несовпадение останавливает сценарий до удаления. Для длинных списков сначала нужен наблюдённый контракт
прокрутки; этот набор не заявляет их поддержку. Добавление должно помещать
упражнение в конец; это проверяется вместе с параметрами и количеством.

Нативный iOS-контракт дополнительно использует `custom.collection`, `custom.close`,
`custom.row.metadata`, `custom.totalDuration`, `custom.remove`, `custom.picked`,
`custom.picker.save`, `custom.edit.intensity`, `custom.wheel`, `custom.wheel.save`.
Метаданные строки содержат интенсивность и длительность в секундах; обе входят
в снимок. Длительность определяется интенсивностью, отдельного редактирования
длительности в наблюдённом UI нет. После добавления интенсивность восстанавливается
через колесо и SAVE; длительность сверяется с исходной. Если добавленная строка
уже полностью совпадает с исходной, редактор не открывается: SAVE без изменений
в этой сборке отключена.
Cancel оставляет редактор открытым: тест закрывает его штатной кнопкой назад,
затем сравнивает весь список. Прокрутка выполняется внутри видимой коллекции;
перед входом и перед восстановлением программы Custom закрывается крестиком.
Перед нажатием Remove и изменением интенсивности элемент прокручивается выше
закреплённой панели; граница определяется координатой видимой SAVE/START WORKOUT.
Одного `visible=true` недостаточно: XCUITest возвращал его и для иконки под панелью.

Восстановление запускается и для Cancel: если дефект удалил упражнение,
исходный список всё равно восстанавливается. В COA-8171 список сохраняется до
мутаций; восстановление закрывает известные диалоги/редактор, удаляет текущие
элементы и добавляет исходные с параметрами в том же порядке. Итог проверяется
по всему снимку. Ошибка восстановления делает тест неуспешным.

## Запуск и проверка

Сначала один кейс на одной платформе с обычными настройками драйвера проекта:

```bash
mvn test -Dplatform=ios \
  -Dtest=tests.KegelOctoberCasesTests#testCoa8096GuideReturnsToSameWorkout \
  -Dcoach.kegelUi.fixture=src/test/resources/kegel/ios-prod-1.13.33.properties \
  -Dios.bundleId=com.vamapps.The-Coach
```

После подтверждения локаторов и данных повторить каждый кейс отдельно для
Android с `-Dplatform=android` и отдельным файлом наблюдённых локаторов.
Пример для подготовленной Android-сессии без профиля (email/OTP кейса и
`COACH_KEGEL_SESSION_EMAIL` уже переданы через окружение):

```bash
mvn test -Dtest=tests.KegelOctoberCasesTests#testCoa8094InfoDescribesCurrentExercise \
  -Dplatform=android -Dandroid.udid=emulator-5556 \
  -Dandroid.deviceName=TheCoach_Android_Retry -Dandroid.platformVersion=16 \
  -Dandroid.appPackage=com.vamapps.thecoach \
  -Dandroid.noReset=true -Dandroid.fullReset=false \
  -Dcoach.kegelUi.fixture=src/test/resources/kegel/android-prod-1.42.1.properties
```

COA-7937 может работать без этого файла, если logout приводит в штатный Welcome.
Для наблюдённого iOS prod передайте prod fixture: она разрешает Quiz как
разлогиненный экран после logout. Это не включает прохождение анкеты или ручной
вход в маркетинговом тесте. Email проверяется среди видимых текстов профиля.

Отдельный запуск COA-7937 после передачи ссылки/email через окружение:

```bash
mvn test -Dtest=tests.KegelOctoberCasesTests#testCoa7937MarketingLinkAutoLogin \
  -Dplatform=ios -Dios.bundleId=com.vamapps.The-Coach \
  -Dios.udid=00CA21E8-4A92-4607-A941-E5FD2E29DAC5 \
  -Dios.deviceName="iPhone 17 Pro" -Dios.platformVersion=26.5 \
  -Dios.isHeadless=true -Dios.noReset=true -Dios.fullReset=false \
  -Dcoach.kegelUi.fixture=src/test/resources/kegel/ios-prod-1.13.33.properties
```

```bash
mvn test -Dtest=tests.KegelOctoberCasesTests#testCoa7937MarketingLinkAutoLogin \
  -Dplatform=android -Dandroid.udid=emulator-5554 \
  -Dandroid.deviceName=TheCoach_API_36_Play -Dandroid.platformVersion=16 \
  -Dandroid.appPackage=com.vamapps.thecoach \
  -Dandroid.noReset=true -Dandroid.fullReset=false
```

Android-браузер должен пройти штатный first-run заранее через UI, без входа
в Google. Экран настройки Chrome не является доказательством дефекта автологина.

Полный **этот** набор, после одиночных прогонов:

```bash
mvn test -Dplatform=android -Dtest=suites.KegelOctoberCasesSuite \
  -Dcoach.kegelUi.fixture=/path/to/observed-android-build.properties
```

Открытие настоящей HTTPS-ссылки использует `mobile: deepLink` без принудительного
package/bundleId: проверяется штатная ассоциация app link и редирект.
Требуется поддерживающий команду Appium-драйвер; iOS требует iOS 16.4+.
См. первичные контракты [UiAutomator2](https://github.com/appium/appium-uiautomator2-driver#mobile-deeplink)
и [XCUITest](https://github.com/appium/appium-xcuitest-driver/blob/master/docs/reference/execute-methods.md#mobile-deeplink).
Окно браузера/обычного входа не обходится. Автотест не открывает другие
маркетинговые ссылки и не использует ручную авторизацию как fallback.

Локальные проверки без устройства:

```bash
mvn -q -DskipTests test-compile
mvn -q -Dtest=tests.KegelOctoberDataUnitTests,tests.RestoringTestActionUnitTests test
```

Они подтверждают компиляцию, маскирование новых учётных данных/ссылки в
артефактах и поведение существующего механизма finally при ошибках сценария
или восстановления. Они не подтверждают работоспособность локаторов,
реальный автологин или восстановление упражнения на устройстве.

## История прогонов, начиная с 10 октября 2026

Все разделы ниже сохраняют последовательность прежних проверок и исправлений.
Указания на отсутствовавший Android fixture или блокеры подготовки описывают
состояние соответствующей попытки; позднее продолжение Android приведено в конце.
Пути `target/...` обозначают локальные артефакты исторических запусков, которые
не входят в эту публикацию. Новые UI-прогоны при подготовке документа не выполнялись.

Appium 2.19.0 запущен локально. Обычная iOS-сессия не создалась из-за отсутствия
`Simulator.app` по ожидаемому пути; повтор с `ios.isHeadless=true` успешно
открыл WDA и приложение. Смена способа запуска не меняла данные приложения.

**iOS 26.5, iPhone 17 Pro Simulator, prod com.vamapps.The-Coach 1.13.33.**
В отдельной UI-инспекции исходным экраном был Welcome без авторизации.
Предоставленная SIAS(M)-ссылка открыла Quiz → Goals («WHAT DO YOU WANT TO ACHIEVE?»).
Авторизованный Today не наблюдался. Затем формальный автотест завершился ошибкой
на подготовке: `Start screen title is not displayed`; штатный back из Quiz
