# Физические iOS RC-прогоны

Эти дополнения расширяют существующие Page Objects и JUnit-тесты для запуска
на установленной TestFlight-сборке. Они не заменяют требования к данным
конкретного кейса и не означают, что полный регресс завершён успешно.

## Подключение и доказательства

Используется bundle-ID attach: не задавайте `ios.app` / `IOS_APP`, укажите
свои `ios.udid`, `ios.bundleId`, `ios.noReset=true`, `ios.fullReset=false`.
Аккаунты и OTP передаются через существующие переменные из
[smoke-environment.md](smoke-environment.md) и
[bookmarks-automation.md](bookmarks-automation.md).

`UpdateEvidence` получает установленную версию и номер сборки через
`xcrun devicectl`. Для аналитики и Today-контента поддержаны Coach prod,
For Her prod и preprod bundle IDs. Чтение контейнера приложения требует
подключённого доверенного устройства и разрешённого доступа к контейнеру.

`scripts/ios_device_evidence.py` копирует только необходимые app-container
файлы во временный каталог. Базы открываются read-only и удаляются после
чтения. В отчёт попадают разрешённые поля проверки, а не исходная база,
JWT или пользовательские свойства. Проверки UID, свежести события и
`program_id` сохраняются и для физического устройства.

Видео селектора на iPhone записывается через текущий IOSDriver; разбор
кадров использует уже применяемый проектом `ffmpeg`. Настройки записи
восстанавливаются при завершении и ошибке.

## Установка через внешний TestFlight-coordinator

`TestFlightHandoff` — опциональный файловый протокол с внешним установщиком.
Он сам не управляет интерфейсом TestFlight. Координатор конкретного стенда
нужно запускать отдельно; локальные скрипты прогона и аккаунты в репозиторий
не входят.

Для каждого запуска создайте новый отдельный каталог и задайте:

- `coach.ios.testFlightHandoff` — каталог обмена; для Bookmarks поддержан
  также `coach.bookmarks.testFlightHandoff`;
- `coach.run.appBuild` — фактический целевой номер RC;
- `coach.ios.previousBuild` / `coach.bookmarks.previousBuild` — другой
  подтверждённый номер предыдущей сборки для update-кейсов.

Тест создаёт `<phase>.request.json` с фазой, текущим Appium session ID,
целевыми bundle/build и временем запроса. Поддержаны `prepare-clean-rc`,
`install-previous`, `install-rc`, `reinstall-rc`, `ensure-rc`.

Координатор должен выполнить именно запрошенную операцию и проверить
установленное приложение через `devicectl`. Для clean/reinstall требуется
реальное удаление и установка; наличие нужного build само по себе не
доказывает переустановку. Для update нужно сохранить данные приложения.
Сохраняйте доказательства операций и восстановления настроек стенда.

После проверки координатор создаёт `<phase>.done`: первая строка `done`,
дальше JSON с `phase` и массивом `after`, содержащим ровно одно приложение
с фактическими `bundleIdentifier` и `bundleVersion`. Java-хук сверяет фазу,
bundle и build; достоверность самой операции обеспечивает координатор.
Ответ от предыдущего запуска повторно использовать нельзя. Ошибка
координатора передаётся файлом `<phase>.coordinator-error`.

Ожидание ограничено 30 минутами; Appium-сессия поддерживается heartbeat.
Один физический телефон должен принадлежать одному последовательному
прогону, включая работу установщика. `ios.sessionBundleId` /
`IOS_SESSION_BUNDLE_ID` позволяет отдельной управляющей сессии подключаться
к другому приложению, сохраняя `ios.bundleId` как тестовую цель.

## Условные экраны и фикстуры

Обработчики закрывают распознанные onboarding/Explore, feedback, email,
notification и Guide-экраны. Ошибка закрытия не считается успешным
восстановлением. Подготовка программы/дня и восстановление выполняются
существующим `RestoringTestAction`; исходное состояние сверяется.

Bookmarks-проверки различают доступный base lesson, активную подписку,
недоступный контент и повторяющиеся практики. Premium не доказывает
активный trial или покупку отдельного мастеркласса. Для recurring-практики
нужны два согласованных дня и проверенные исходные completion-маркеры.

Создание/привязка подготовительной учётной записи вынесено в существующий
opt-in `IOSRegressionFixturePreparationTests` (`coach.fixture.prepare=true`).
Покупки требуют отдельных Sandbox/purchase flags и распознанной native
маркировки тестовой покупки. Для trial дополнительно проверяется предложение
бесплатного периода в native StoreKit sheet.

## Ограничения проверки

Process-language режим локализации проверяет строки и перезапуск с явными
аргументами; он отдельно помечен и не доказывает наследование/приоритет
системного языка. Визуальный oracle шапки использует независимый COA-8772
reference из `src/test/resources/modules/coa8772-header.png`.

Cold-launch тест `IOSStartupStabilityTests` наблюдает процесс и доступность
UI до обработки условных экранов. Для него `coach.ios.testFlightReports`
должен быть `false`, чтобы сообщение о краше не закрывалось автоматически.

Полный регресс RC 3582/3583 на момент публикации не завершён. В частности,
остаются ограничения данных/entitlement, готовности списка Bookmarks,
module/day popup, конечной позиции видео и визуального skeleton detector.
Они не обходятся снятием assertion или изменением теста ради PASS.
Актуальные результаты ведутся отдельно в Xray:
[man](https://the-coach.atlassian.net/browse/COA-9755),
[woman](https://the-coach.atlassian.net/browse/COA-9756).

Offline unit-проверки транспорта, локаторов, восстановления и защит
StoreKit не заменяют прогоны приложения. Публикация этих изменений не
является подтверждением готовности релиза или Android device parity.
